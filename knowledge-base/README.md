## 内容组织原则

在组织内容结构时，需要根据信息类型选择合适的展示形式：

### 表格适用场景

| 场景 | 特点 | 示例 |
|---|---|---|
| **多维对比** | 多个对象在多个维度上的横向对比 | 不同微调方法的参数量、显存、适用场景对比 |
| **结构化数据** | 具有明确字段的规范化数据 | 训练范式的谱系表（范式/数据/目标/适用模型） |
| **清单/矩阵** | 需要快速查阅的参考信息 | 配置参数表、决策矩阵 |

### 嵌套列表适用场景

| 场景 | 特点 | 示例 |
|---|---|---|
| **层级关系** | 类别→子项的树状结构 | 核心目标分类（5类→11个目标） |
| **详细展开** | 需要较长文字解释的内容 | 概念定义、原理说明 |
| **流程/步骤** | 有先后顺序的操作序列 | 训练流程、决策树 |

### 避免的问题

| 问题 | 原因 | 解决方案 |
|---|---|---|
| **类别重复** | 表格每行都要写类别名称 | 用嵌套列表，类别作为标题只出现一次 |
| **拆表过多** | 每个类别单独一个表格 | 用嵌套列表保持整体性 |
| **列宽限制** | 详细说明被截断 | 用嵌套列表完整展开 |

### 决策参考

```
需要展示的信息是什么？
    ↓
├─ 多个对象的多维对比 → 表格
├─ 层级分类 + 详细展开 → 嵌套列表
├─ 流程/步骤/决策树 → 嵌套列表或代码块
└─ 单一概念解释 → 普通段落
```

## 更新流程

除非用户直接要求修改文件，否则本知识库默认采用 **草稿-审核-合并** 模式更新，确保每次修改都经过用户确认：

### **草稿-审核-合并** 模式流程

1. **写入草稿**：将待审核内容写入 `draft.md` 文件
2. **审核调整**：用户在草稿文件中提出修改意见，AI 继续调整
3. **合并确认**：用户满意后，将草稿内容合并到对应主文件
4. **清空草稿**：合并完成后，清空 `draft.md` 内容（保留文件）

### 文件说明

- `draft.md` 为 **常驻草稿文件**，始终存在于 `knowledge-base/` 目录中
- 合并完成后只清空内容，不删除文件
- 草稿文件同一时间只处理一个修改任务（覆盖写入）

### 注意事项

- `draft.md` 中的内容为 **待审核状态**，仅供参考
- 只有主目录中除 `draft.md` 外的 `.md` 文件才是权威版本
- 草稿文件可随时修改，无需顾虑版本管理
