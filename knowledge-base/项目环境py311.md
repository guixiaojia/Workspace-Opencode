## 三、总 · 整理建议与执行计划

回到全局：这个环境该怎么拆、怎么清、怎么补、怎么锁。执行顺序即表格顺序，第 0 步不做完不要往下走。

| 阶段 | 动作 | 具体命令 / 做法 | 目的 |
|---|---|---|---|
| 第0步 留快照 | 导出当前环境，任何操作前先可回滚 | pip freeze > requirements_py311_20260908.txt；conda env export > env_py311.yaml | 误删可一键恢复 |
| 第1步 看依赖树 | 区分「你装的」与「被带进来的」 | pip install pipdeptree；pipdeptree --json-tree > tree.json | 只有顶层包才需要你决策，其余别手动删 |
| 第2步 拆环境 | 按 4 个场景拆：cv（分割/视觉）、llm（训练/微调）、rag（Agent/检索）、web（服务与演示） | conda create -n cv python=3.11；conda create -n llm python=3.11；conda create -n rag python=3.11；conda create -n web python=3.11 | 避免 torch/CUDA 与 Web/Agent 依赖互相锁版本 |
| 第3步 去冗余 | 同类只留一个：PyPDF2 vs PyMuPDF；gradio vs dash vs flask vs fastapi；modelscope vs openxlab vs opendatalab；langchain-classic 为兼容层 | pip uninstall PyPDF2 langchain-classic（确认无代码 import 后） | 减少依赖冲突面 |
| 第4步 补评估 | 评估类目前只有 rouge、thop，明显偏薄 | pip install torchmetrics evaluate sacrebleu torchinfo fvcore（CV 再加 pycocoevalcap） | 覆盖分类/检测/分割/生成等指标 |
| 第5步 锁版本 | 固定关键版本，保证可复现 | pip freeze > requirements.txt 并按 torch/transformers 锁定；用 pip-compile 管理 | 实验可复现，环境可迁移 |
| 第6步 定期体检 | 每季度检查一次冲突与废弃 | pip check；pip list --outdated；pip-audit | 提前发现 ABI 冲突与安全漏洞 |
