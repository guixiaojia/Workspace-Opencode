# 0. 总体框架：自动驾驶大模型训练到底在设计什么？

自动驾驶大模型的训练策略，可以抽象成相互独立、但最终需要组合起来考虑的**三个正交的设计维度**。：

| 维度 | 核心问题 | 决定什么 |
|---|---|---|
| **参数状态** | **训练谁？** | 哪些模块冻结、部分训练或全部训练 |
| **微调方法** | **怎么更新？** | 参数采用全参数、LoRA、Adapter 等什么方式更新 |
| **训练范式** | **学什么？** | 用什么数据、监督信号和目标函数驱动模型学习 |

> 举例分析：
> 冻结 ViT + 训练 Projector + LLM LoRA + SFT
> **参数状态 = 训练谁**：冻结 ViT，训练 Projector，部分训练 LLM
> **微调方法 = 怎么训练**：LLM 使用 LoRA
> **训练范式 = 训练什么能力**：SFT

注意！！！不能把“LoRA”“冻结 LLM”“SFT”放在同一个层级比较。

# 1. 第一层：参数状态——训练谁？

## 1.1 先把一个 AD 大模型拆开

VLM4AD / VLA4AD / World Model 往往由多个组件构成：

| 模块 | 主要作用 | 典型实现 |
|---|---|---|
| **Vision Encoder** | 图像 / 多视角图像 → Visual Tokens | CLIP / SigLIP / DINOv2 / Qwen-ViT |
| **Projector** | Visual Tokens → LLM Embedding Space | MLP / Q-Former / Resampler |
| **LLM Backbone** | 场景理解、推理、语言生成 | Qwen / LLaMA / Vicuna |
| **Action Head** | 输出轨迹、动作或控制量 | MLP / Diffusion / Flow Matching |
| **World Model Decoder / Dynamics Model** | 预测未来帧或未来隐状态 | DiT / UNet / 隐空间预测器 |

因此训练时首先要决定：哪些模块全部冻结？哪些模块部分训练？哪些模块全部训练？

## 1.2 参数状态的三个基本选择

| 状态 | 说明 | 优点 | 缺点 | 典型场景 |
|------|------|------|------|---------|
| **Frozen** | 完全冻结，参数不参与反向传播 | 节省显存、保留预训练能力、减少灾难性遗忘、训练稳定 | 模型适应新领域能力有限 | Vision Encoder、冻结的 LLM |
| **Partial** | 只训练模块的一部分参数（如最后几层、Attention 层、LoRA、Adapter 等） | 折中方案，平衡效率与适应性 | 需要设计具体的部分训练策略 | LLM LoRA、ViT 最后 k 层 |
| **Full** | 整个模块全部参与训练 | 最大适应能力、理论性能上限更高 | 显存/计算成本高、数据需求大、灾难性遗忘风险高 | Projector、Action Head |

## 1.3 不同模块应该怎么处理？

| 模块 | 主要作用 | 推荐策略 | 经验说明 |
|------|---------|----------|---------|
| **Vision Encoder** | 图像/多视角图像 → Visual Tokens | 冻结为主，特殊情况 Partial/Full | 自然图像冻结即可（CLIP/SigLIP 已具备强表征能力）；BEV/Occupancy/深度图等非自然输入可能需要开放训练 |
| **Projector** | 视觉空间 → LLM 语义空间的"翻译层" | 通常 Full 训练 | 参数量小、成本最低；不训练则 LLM 直接接受陌生视觉 token 分布 |
| **LLM Backbone** | 场景理解、推理、语言生成 | 冻结 / LoRA / Partial / Full 视情况 | 数据少→冻结；数据适中→LoRA；数据充足+追求上限→Full FT |
| **Action Head** | 输出轨迹、动作或控制量 | 通常 Full Fine-Tune | 规模较小，输出连续动作（非离散 token），使用 LoRA 意义有限 |
| **World Model** | 预测未来帧或未来隐状态 | 冻结 Tokenizer + 训练 Dynamics Model + 训练规划头 | 核心思想：冻结"如何表示世界"，训练"世界如何变化" |

## 1.4 典型训练方案

| 方案 | 冻结/训练配置 | 典型用途 |
|---|---|---|
| **① 只训 Projector** | 冻结: ViT + LLM，训练: Projector | 视觉-语言对齐、数据少 |
| **② Projector + LLM 全训** | 冻结: ViT，训练: Projector + LLM | 数据充足、追求性能 |
| **③ ViT + Projector + LLM 全训** | 冻结: 无，训练: 全部 | 域差异非常大 |
| **④ ViT 冻结 + Projector + LLM LoRA** | 冻结: ViT，训练: Projector + LoRA | **VLM4AD 常见方案** |
| **⑤ VLM 冻结 + Action Head** | 冻结: ViT + Projector + LLM，训练: Action Head | **VLA 常见方案** |
| **⑥ Tokenizer 冻结 + Dynamics Model** | 冻结: VAE / Tokenizer，训练: DiT / Dynamics | **World Model 常见方案** |

这里需要特别注意：**“冻结 + 部分微调”** 不是一种固定方案，而是一整个设计空间。真正需要调研的是：

```text
冻结谁？
    ↓
部分训练谁？
    ↓
训练比例是多少？
    ↓
为什么这样组合？
    ↓
对性能 / 显存 / 泛化 / 遗忘有什么影响？
```

实际训练中，不是一次决定所有参数，不一定从头到尾使用同一套参数状态。可以采用分阶段训练：

```text
阶段 1 视觉-语言对齐 (只训练 Projector)
阶段 2 多模态指令学习 (Projector + LLM LoRA)
阶段 3 驾驶领域适配 (Projector + LLM LoRA + 可选 Vision Encoder)
阶段 4 动作学习 (Action Head + Projector + LLM LoRA)
阶段 5 闭环对齐 (Action Head + LLM LoRA + Critic / RL)

```

这样做的核心思想是：**随着模型能力目标从“看懂”逐渐走向“会开”，逐步扩大训练自由度。**

# 2. 第二层：微调方法——确定"训练谁"以后，这些参数采用什么方式更新？

## 2.1 微调方法有哪些

| 微调方法 | 核心思想 | 更新方式 | 可训练参数比例 | 显存需求 | 适用场景 | 主要优点 | 主要缺点 | 关键配置参数 |
|---|---|---|---|---|---|---|---|---|
| **Full Fine-Tuning** | 直接更新目标模块的全部参数 | `W → W'` | 100% | 最高 | 数据充足、算力充足、追求性能上限 | 表达能力最强，理论性能上限最高 | 显存/计算成本高，数据需求大，灾难性遗忘风险高 | 学习率（1e-5 ~ 2e-5） |
| **LoRA** | 增加低秩更新，不修改原始权重 | `W' = W + (α/r)BA` | 0.1% ~ 1% | 低 | 默认 PEFT 方法，大模型微调 | 参数量大幅减少，显存占用低，可针对不同任务保存不同 LoRA，部署时可 Merge 回原模型 | 表达能力受限于 rank，对小模块意义有限 | rank（8~64）、target_modules、learning rate（1e-4 ~ 2e-4） |
| **QLoRA** | 量化 + LoRA | 4-bit 量化冻结 + LoRA | 与 LoRA 相同 | 极低（比 LoRA 再降） | 单卡训练、大模型、显存有限（如 24G GPU 训练 7B 模型） | 进一步降低显存，使单卡训练大模型成为可能 | 主要价值是降显存而非提速度，量化可能引入精度损失 | 量化位数（4-bit）、rank、target_modules |
| **DoRA** | 将权重分成幅度 + 方向 | 分解权重为幅度和方向分别更新 | 较低 | 低 | 逼近 Full FT 效果 | 理论上比标准 LoRA 更接近 Full FT 表达能力 | 实现相对复杂 | rank、分解方式 |
| **AdaLoRA** | 动态分配不同层的 rank | 根据层重要性自适应调整 rank | 较低 | 低 | 层重要性差异明显的情况 | 自适应分配资源，重要层获得更多参数 | 需要额外计算重要性指标 | 目标 rank 范围、重要性评估方法 |
| **Adapter** | 插入小型瓶颈网络 | 在层间插入瓶颈结构 | 较低 | 低 | 多任务切换 | 多任务间切换方便，参数隔离 | 增加额外推理路径，可能影响推理速度 | 瓶颈维度、插入位置 |
| **Prompt Tuning** | 学习软 prompt | 只训练输入前缀向量 | 极低 | 极低 | 参数量极低场景 | 参数量极低，训练极快 | 表达能力有限，不适合复杂任务 | prompt 长度、初始化方式 |
| **OFT / BOFT** | 学习正交变换 | 通过正交矩阵变换权重 | 较低 | 低 | VLA 等场景 | 保持权重矩阵的正交性，训练稳定 | 实现复杂度较高 | 正交约束强度 |
| **VPT** | Vision Prompt Tuning | 在 ViT 输入前添加可学习 prompt | 极低 | 极低 | ViT 微调 | 参数量极低，适用于视觉模型 | 仅限视觉模型，表达能力有限 | prompt 长度、位置 |
| **AdaptFormer / Convpass** | ViT 内插 Adapter / 分支 | 在 ViT 层间插入适配器或分支 | 较低 | 低 | 视觉侧微调 | 专门优化视觉模型，适配效果好 | 仅限视觉模型，需要设计插入结构 | 适配器维度、插入层位置 |
| **SSF** | 学习缩放和偏移 | 对特征进行缩放和偏移变换 | 极低 | 极低 | 视觉模型轻量微调 | 极其轻量，训练极快 | 表达能力有限 | 缩放/偏移初始化方式 |

## 2.2 选择决策参考

| 条件 | 推荐方法 | 原因 |
|---|---|---|
| 单卡 24G GPU | QLoRA | 显存受限，QLoRA 可训练 7B 级模型 |
| 单卡 80G GPU | bf16 LoRA / 部分 Full FT | 显存充足，可选择更高精度 |
| 多卡训练 | Full FT / 大 Rank LoRA | 算力充足，可追求更高性能 |
| 多机多卡 | Full SFT + DPO / PPO 等 | 完整训练流程，包括偏好对齐 |
| 数据量 < 5 万 | LoRA（r=8~16） | 数据有限，LoRA 足够 |
| 数据量充足 | LoRA（r=32~64）或 Full FT | 数据充足时可考虑更高表达能力 |
| 追求性能上限 | Full FT | 理论性能上限最高 |
| 多任务切换 | Adapter | 参数隔离，切换方便 |
| 参数量极低要求 | Prompt Tuning / VPT | 参数量极低 |
| 视觉模型微调 | VPT / AdaptFormer / SSF | 专门为视觉模型设计 |

# 3. 第三层：训练范式——模型到底学习什么？

前面两个问题：

```text
参数状态 → 训练谁？
微调方法 → 怎么更新？
```

第三个问题是：

> **用什么数据、什么监督信号、什么目标，让模型获得目标能力？**

这就是训练范式。

---

## 训练范式谱系

| 范式 | 数据 | 核心目标 | 适用模型 | 监督类型 | 开环/闭环 | 主要解决的问题 |
|---|---|---|---|---|---|---|
| **CPT** | 原始语料/日志 | 下一Token预测 | VLM/VLA | - | 开环 | 领域知识 |
| **模态对齐预训练** | 图像-文本 | 图文对应 | VLM/VLA | 语言监督 | 开环 | 视觉进入语言空间 |
| **SFT** | 指令-回答 | 监督学习 | VLM/VLA | 语言监督 | 开环 | 指令遵循 |
| **CoT SFT** | 问题-推理链-答案 | 学习推理过程 | VLM/VLA | 语言监督 | 开环 | 推理能力 |
| **DPO/IPO/KTO** | chosen/rejected | 偏好优化 | VLM/VLA | 语言监督 | 开环 | 输出质量、安全 |
| **RLHF/PPO** | 奖励模型+采样 | 策略优化 | VLM/VLA | 语言监督 | 开环 | 不可微整体指标 |
| **RLVR** | 有客观判据的数据 | 可验证奖励 | VLM/VLA | 语言监督 | 开环 | 客观正确性 |
| **BC** | 专家轨迹 | 模仿专家 | VLA | 轨迹监督 | 开环 | 动作学习 |
| **DAgger** | 在线纠偏轨迹 | 减少分布漂移 | VLA | 轨迹监督 | **闭环** | 闭环驾驶 |
| **闭环RL** | 仿真交互 | 奖励优化 | VLA | 轨迹监督 | **闭环** | 真正驾驶能力 |
| **World Model Training** | 连续状态+动作 | 未来预测 | World Model | 轨迹监督 | - | 学习环境动力学 |

**数据**：该范式训练时使用的数据形式。不同范式对数据格式要求不同，例如：
- CPT 使用原始语料
- SFT 使用指令-回答对
- BC 使用专家驾驶轨迹
  
**核心目标**：该范式优化的核心方向。按自动驾驶与具身智能大模型的能力构建逻辑，可分层展开如下：

#### 1. 基础表征与感知

- **下一Token预测**：通过自回归方式学习多模态序列的统计规律，赋予模型基础的物理世界常识、交通领域知识以及语言/动作序列的生成能力 → CPT

- **图文对应**：将视觉特征（像素/特征图）映射到语言特征空间，使模型能够"看懂"图像并用语言准确描述，实现跨模态的底层理解 → 模态对齐预训练

#### 2. 认知与任务执行

- **监督学习/指令遵循**：通过"指令-回答"范式，让模型学会听懂人类的具体任务要求（如"识别前方车辆并减速"），将通用知识转化为特定任务的解决能力 → SFT

- **学习推理过程**：不仅学习最终答案，更学习"如何思考"（如思维链 CoT）。提升模型在复杂逻辑、长尾场景（Corner Cases）、物理规则推导等需要多步思考场景下的能力 → CoT SFT

#### 3. 价值与策略对齐

- **偏好优化**：在多个可能的输出（如不同的驾驶决策或文本回复）中，学习人类认为"更好"、"更舒适"或"更安全"的选择，解决模型输出的风格、有用性和无害性问题 → DPO/IPO/KTO

- **策略优化**：通过奖励模型引导，优化模型在复杂交互或长序列生成中的整体策略，使其综合表现更符合人类期望或特定的高阶评价指标 → RLHF/PPO

- **可验证奖励**：针对有明确对错标准（如代码运行结果、数学计算、交通规则判定、碰撞检测）的任务，利用客观反馈信号进行强化，提升结果的绝对准确性和规则遵守度 → RLVR

#### 4. 动作执行与闭环控制

- **模仿专家**：直接学习人类驾驶员或专家的操作轨迹，使模型掌握基础的"感知-动作"映射，学会如何控制方向盘、油门和刹车 → BC

- **减少分布漂移**：在模型自己犯错时引入专家纠偏，打破开环模仿中的误差累积（协变量偏移），提升模型在真实闭环环境中的鲁棒性和容错率 → DAgger

- **奖励优化**：在闭环仿真中，通过试错和长期累积奖励（如安全性、舒适度、通行效率、博弈胜率），优化模型的长程决策、动态避障和复杂路口通行能力 → 闭环RL

#### 5. 环境理解与预测

- **未来预测**：学习环境的物理规律和动力学，使模型能够预测"如果我采取某个动作，未来环境和其他交通参与者会如何变化"，从而支持更安全、更具前瞻性的规划 → World Model Training
**适用模型**：该范式主要适用于哪类自动驾驶模型：
- VLM/VLA：视觉语言模型、视觉语言动作模型都可使用
- VLA：仅视觉语言动作模型使用（需要输出动作）
- World Model：仅世界模型使用

### 监督类型

训练信号的类型，分为两类：
- **语言监督**：用自然语言作为监督信号（QA、描述、推理链），保留语义能力但不直接优化驾驶
- **轨迹监督**：用连续轨迹作为监督信号（L2 loss、collision loss），直接优化驾驶行为但可能退化语言能力

### 开环/闭环

训练时模型是否与环境交互：
- **开环**：模型预测→与GT比较，简单稳定但有分布漂移问题
- **闭环**：模型与环境交互循环，更接近真实驾驶但成本高

### 主要解决的问题

该范式在自动驾驶训练链条中解决的具体问题，例如"领域知识"、"指令遵循"、"闭环驾驶"等。

# 23. 典型方案三：VLA4AD

这是从“理解”走向“行动”的关键方案。

## 23.1 核心结构

```text
Vision Encoder
      ↓
Projector
      ↓
LLM
      ↓
```

# 29. 第六层：训练中的高频问题

| 问题 | 可能原因 | 对策 |
|---|---|---|
| 训练后不会说话 | SFT 过强 / LR 过高 | 加通用指令数据、降低 LR |
| 开环很好、闭环撞车 | Distribution Shift | DAgger / 闭环 RL |
| LoRA 几乎没效果 | LR 太低 / target modules 太少 | 提高 LR、扩大 target modules |
| 多轮训练指标下降 | 灾难性遗忘 | 分阶段训练 + replay |
| VLA 动作抖动 | 帧间预测不一致 | Action Chunking / 时序建模 |
| 视觉能力下降 | Vision Backbone 过度微调 | 冻结或降低视觉侧训练比例 |

# 30. 第七层：架构设计中的核心 Trade-off

训练方案本质上是在做几个权衡。

## 30.1 算力 vs 性能

```text
冻结主干 + LoRA
        ↕
Full Fine-Tuning
```

一般：

> 算力有限 → PEFT  
> 算力充足 + 数据充足 → Full FT

---

## 30.2 通用性 vs 专业性

```text
Frozen Backbone
      ↕
Full Fine-Tuning
```

冻结：

- 保留通用能力
- OOD 泛化可能更好

全参：

- 专业领域适应更强
- 灾难性遗忘风险更高

---

## 30.3 训练效率 vs 部署效率

```text
Adapter
  ↕
LoRA
```

Adapter 可能增加额外推理路径。

LoRA 合并后：

> 可以基本消除额外推理开销。

# 31. 第八层：三维设计空间之间如何相互影响？

前三个维度不是完全独立的。

## 31.1 参数状态 × 微调方法

例如：

> LoRA 主要适合有大量线性层的模块。

因此：

```text
LLM + LoRA
```

非常自然。

而：

```text
小型 Action Head + LoRA
```

意义通常有限，因为 Action Head 本身参数量就不大。

---

## 31.2 微调方法 × 训练范式

训练范式越复杂，对显存和可训练参数的要求往往越高。

例如：

```text
SFT
 ↓
DPO
 ↓
RL
```

训练复杂度逐渐增加。

因此 PEFT / QLoRA 等方法可以帮助降低训练成本。

---

## 31.3 参数状态 × 训练范式

不同训练阶段需要不同的训练自由度。

例如：

```text
小数据 SFT
→ 不适合直接 Full FT

闭环 RL
→ 需要更强的策略更新能力
```

因此：

> **参数状态不能脱离训练范式单独决定。**

# 32. 第九层：最终评价标准——不要只看训练指标

对于普通 LLM：

```text
Loss
↓
Benchmark
↓
能力
```

但对于自动驾驶模型：

```text
训练 Loss
     ↓
开环指标
     ↓
闭环指标
     ↓
真正驾驶能力
```

因此最终不能只看：

- Language Loss
- QA Accuracy
- L2

还需要关注：

- Collision Rate
- Driving Score
- PDM Score
- 闭环稳定性
- 安全性
- 泛化能力

最终原则：

> **训练策略最终必须回到“模型在闭环环境中是否真的更会开车”。**

# 34. 一句话记忆

> **参数状态决定“训练谁”，微调方法决定“怎么更新这些参数”，训练范式决定“让模型学什么能力”，三者组合起来才构成完整的自动驾驶大模型训练方案。**

进一步可以记成：

> **训练谁 → 怎么改 → 学什么 → 怎么组合 → 怎么验证**

而对于自动驾驶：

> **最终不是“模型 Loss 降了多少”，而是“模型在闭环环境里是否真的更会开车”。**
