# 显存估算框架（组件级）

> 自动驾驶模型训练/推理的显存需求估算方法，按组件粒度拆解，适用于任何技术路线。

---

## 核心思想

显存估算不再按论文逐行罗列，而是：
1. 按**组件类型**估算（Visual Encoder、LLM、Action Head 等）
2. 按**微调状态**区分（冻结/推理 vs 微调）
3. 用户根据论文的**技术路线**，自行累加各组件显存

## 显存速查矩阵

**使用方法**：
1. 确定论文的**技术路线**
2. 确定使用的 **LLM 规格**
3. 确定**微调方式**
4. 查表或累加各组件显存

| 输入条件 | → 显存估算 |
|----------|------------|
| BEV-VLM + LLM-7B + LoRA | 0.6(Enc) + 0.2(BEV) + 0.04(Proj) + 14.4(LLM) = **~15.2GB** |
| Modular VLA + LLM-7B + QLoRA | 0.6(Enc) + 0.04(Proj) + 0.04(Action) + 3.9(LLM) = **~4.6GB** |
| WM VLA + LLM-14B + LoRA | 0.6(Enc) + 0.04(Proj) + 0.04(Action) + 28.8(LLM) + 14.4(WM) = **~44GB** |

## NVIDIA 优化栈说明

| 优化技术 | 显存节省 | 速度影响 | 适用场景 |
|---------|---------|---------|---------|
| **BF16/FP16 混合精度** | 权重/梯度 -50% | 基准 | 所有 Ampere+ GPU |
| **FlashAttention-2** | 激活值 -80~90% | +10~20% | 需 Ampere+，必装 |
| **Gradient Checkpointing** | 激活值 -60~70% | -30% | 显存极限场景 |
| **DeepSpeed ZeRO-2** | 优化器 -50% | -15% | 多卡训练 |
| **DeepSpeed ZeRO-3** | 优化器 -75% + 权重分片 | -25% | 多卡训练 |
| **INT8 量化推理** | 权重 -50% | -5% | 仅推理 |
| **INT4 (GPTQ/AWQ)** | 权重 -75% | -10% | 仅推理 |
